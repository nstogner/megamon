## Project Overview

MegaMon provides metrics related to running JobSets and Nodepools on top of Kubernetes. In particular for TPU workloads. It makes assumptions around how TPU node pools are provisioned. In particular it assumes nodepools are provisioned via <https://github.com/ai-on-gke/tpu-provisioner>

### Reference objects

- docs/reference/`example.nodepool` is YAML from GKE nodepool API, with valid labels
- docs/reference/`example.node` is YAML from k8s Node object, with valid labels

### Object relationships

- k8s Nodes belong to a GKE NodePool
  - O(1000) nodes per nodepool
  - O(100) nodepools per cluster
- O(100) jobsets. Jobs belong to a jobset
  - O(1000) jobs
- with slicing e.g. SliceEnabled == true
  - O(100) slices
  - 16 nodes per nodepool
  - O(100) node pools
  - O(100) jobsets
    - jobsets target a slice via partition IDs
    - a slice is made up of 1 or more partition IDs
  - node belongs to 1 slice and 1 nodepool
  - a slice may contain 1 or more nodepools
  - a slice may contain 1 or more subblocks
  - a slice may contain 1 or more logical blocks (block name), but only 1 physical block (block id)
  - a block contains 1 or more sub blocks
  - 1 subblock is 16 nodes
  - a nodepool belongs to a distinct subblock
  - O(100) subblocks per block
  - Block and SubBlock are only present when SliceEnabled == true
  - a slice can only belong to a single block, a slice may have 1 or more subblocks

### Slice CRD

- valid states are ACTIVE, ACTIVE_DEGRADED, ACTIVATING, INCOMPLETE, DEACTIVATING, FAILED or UNKNOWN

### Slicing vs Non-Slicing Mode (`SliceEnabled`)

MegaMon operates in two mutually distinct modes controlled by the `SliceEnabled`
configuration:

- **Why Slice CRDs must NOT be watched when `SliceEnabled == false`**:
  - The Slice CRD (`accelerator.gke.io/v1beta1`) is optional
  - If `controller-runtime` registers a watch on a CRD is not registered in the Kubernetes API server, manager startup will fail
  - When `SliceEnabled == false`, `WorkloadReconciler` watches `corev1.Node` instead of `Slice`, and `slices.json` is omitted from the required startup keys in `EventLog.IsPopulated`.
- **Why `jobset_nodes` metrics are omitted when `SliceEnabled == true`**:
  - When slicing is used, the slice is the unit of scheduling and failure domain, rather than the node pool.
  - Slices are mapped to JobSets via `tpu-provisioner.cloud.google.com/owner-*` labels
  - Emitting `jobset_nodes` metrics when slicing is enabled is superseded by Slice metrics (`megamon.slice.*`).

### Kubebuilder

- **No Kubebuilder markers for Slice resources in `workload_reconciler.go`**:
  - Do **not** add `// +kubebuilder:rbac:...` annotations for `accelerator.gke.io` / `slices` in [internal/controller/workload_reconciler.go](internal/controller/workload_reconciler.go).
  - RBAC rules generated by `make manifests` are written to `config/rbac/role.yaml` for default cluster roles. Because the Slice CRD is optional and not present on clusters where slicing is disabled, adding markers to Go code would enforce Slice permissions in base manifests.
  - Slice RBAC is intentionally managed separately via Kustomize overlays in `config/default-slice/` and `config/dev-slice/`.
